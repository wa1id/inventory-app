Test fixtures for InventoryCoreTests.

The JSON files are parity vectors generated by running the real TypeScript
(`src/core`, `src/services/account/base32.ts`, `src/ui/{code,placeMatch,a11y,color}.ts`,
`codeProblem` and `serverHost` from `src/ui/household/join.ts`, `parseQrPayload` from
`src/repositories/qr.ts`, and the `search_text` / tag folds of `src/repositories/items.ts`,
restated verbatim in the generator because they are not exported).
`config.json` and `errors.json` come from `src/services/config.ts`, `src/ui/errors.ts` and `joinFailure` in `src/ui/household/join.ts`.
Do not edit them by hand; regenerate with `generator/core-vectors.test.ts` and
`generator/app-vectors.test.ts` (their headers have the commands).

| File | Contents |
| --- | --- |
| `folding.json` | A broad Unicode corpus (spec §6.6 examples, Greek sigma contexts, compatibility forms, case mappings up to Unicode 16, scripts, emoji, white space, format characters, QR payloads, seeded random strings) with each input's code points and JS `toLowerCase`, `toUpperCase`, `trim`, `tokenizeQuery`, `compactAlphanumeric`, `placeTerms`, `toLikePattern`, `normalizeShortCode`, `normaliseCode`, `invalidCodeChars`, `spellCode` and `parseQrPayload` |
| `storedText.json` | `items.search_text` (`${name} ${category ?? ''}`.trim().toLowerCase()) and `tags.normalized_name` over the corpus |
| `base32.json` | Crockford base32 encode/decode/format vectors and account ids for fixed secrets |
| `ids.json` | `newId` / `newQrToken` from fixed bytes |
| `quantity.json` | `parseQuantityInput` (JS `Number()` grammar) and `clampQuantity` |
| `codes.json` | Short-code prefixes, code normalisation, `codeProblem`, `serverHost` |
| `placeMatch.json` | `matchesPlace` over options × queries, with the English type names |
| `a11y.json` | `whereSpoken`, `quantitySpoken`, `spellCode`, and the strings.ts copy they use |
| `color.json` | `safeColor`, `rgb`, `toHex`, `mixHex`, `spaceTint`, `withAlpha`, `luminance`, `contrast` |
| `config.json` | `appConfig` for each tricky value of every `EXPO_PUBLIC_*` variable (timeouts as the raw JS number) |
| `errors.json` | `describeError` over household errors (status × code, plus odd statuses and codes), conflicts, `null`, `Error` and `undefined`, × every context × subject; plus `needsRefreshBanner`, `isOffline` and `joinFailure` |

Unicode 17 additions are kept out of the corpus: Node 24 knows them but the macOS 15
test host does not, so they would test the host's tables rather than this code.
